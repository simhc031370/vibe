# UPDF 분석 (REA) 및 vPDF 설계

## 1. 범위와 방법

- **REA 해석**: 저장소에 UPDF 바이너리나 "REA" 도구가 없어서 REA를 *Reverse-Engineering Analysis*(역설계 분석)로 해석했습니다.
- **방법**: 상용 바이너리를 디컴파일하지 않았습니다(라이선스/법적 이유). 대신 공개 정보(공식 웹사이트, 제품 소개·도움말, 앱 스토어 설명)를 바탕으로 **기능 단위로 분해(black-box 분석)** 하고, 이를 오픈소스 스택으로 재구성했습니다.
- **주의**: 내부 구현(렌더링 엔진, OCR 엔진 등)은 공개적으로 확인되지 않았으므로 아래 "추정"으로 표기한 내용은 가설입니다.

## 2. 제품 개요

| 항목 | 내용 |
| --- | --- |
| 제품 | UPDF (Superace Software Technology) |
| 분류 | AI 기능을 포함한 올인원 PDF 편집기 (Adobe Acrobat 대체 포지션) |
| 플랫폼 | Windows, macOS, iOS, Android (하나의 계정/라이선스로 여러 기기에서 사용) |
| 과금 | 무료 체험(워터마크 등 제한) + 연간/영구 라이선스, AI 기능은 별도 애드온 |
| 차별점 | 가벼운 네이티브 앱, 깔끔한 UI, AI 요약/번역/채팅, 클라우드 동기화 |

## 3. 기능 분해 (Feature map)

| 영역 | UPDF 기능 | 핵심 기술 요소 |
| --- | --- | --- |
| 읽기 | 페이지 렌더링, 썸네일, 확대/축소, 단일·연속·양면 보기, 텍스트 검색, 북마크, 슬라이드쇼 | PDF 파싱/래스터화, 텍스트 추출 |
| 주석 | 형광펜, 밑줄, 취소선, 메모(스티키 노트), 텍스트 상자, 도형, 연필, 도장, 스티커, 서명 | PDF Annotation 객체(/Highlight, /Text, /Ink, /Stamp …) |
| 편집 | 기존 텍스트/이미지/링크 직접 편집, 워터마크, 배경, 머리글·바닥글, 베이츠 번호 | 콘텐츠 스트림 수정, 폰트 서브셋 재임베딩 |
| 페이지 구성 | 삽입, 교체, 추출, 분할, 회전, 삭제, 순서 변경, 크롭 | 페이지 트리 조작 |
| 변환 | PDF → Word/Excel/PPT/이미지/텍스트/HTML/XML/CSV/RTF/PDF-A, 이미지 → PDF | 레이아웃 분석, 래스터화, OCR |
| OCR | 스캔본을 검색·편집 가능한 PDF로 (다국어) | OCR 엔진 + 보이지 않는 텍스트 레이어 |
| AI | 요약, 번역, 설명, PDF와 채팅, 마인드맵 | 텍스트 추출 + 클라우드 LLM API |
| 보안 | 열기/권한 암호, 민감 정보 가리기(Redaction) | PDF 암호화(RC4/AES), 콘텐츠 실제 삭제 |
| 양식/서명 | 양식 채우기, 양식 만들기, 전자 서명 | AcroForm 필드, 서명 외형 스트림 |
| 일괄 처리 | 일괄 변환, 병합, 삽입, 인쇄, 암호화 | 위 기능의 배치 실행 |
| 기타 | 압축, 비교, 클라우드 저장소, 인쇄 | 이미지 재압축, 객체 정리 |

## 4. 구조 추정

```text
UI 셸 (네이티브: Windows/macOS/모바일)
 ├─ 모드 레일: 읽기 / 주석 / 편집 / 페이지 구성 / 도구 / AI
 ├─ 문서 모델: PDF 파서 + 렌더러 (자체 또는 상용 SDK, 미확인)
 ├─ 편집 계층: 주석 객체, 콘텐츠 스트림 편집, 페이지 트리 조작
 ├─ 변환 계층: 레이아웃 분석 → Office 포맷 출력, OCR 엔진
 └─ 서비스: 계정/라이선스, 클라우드 동기화, AI(LLM API)
```

UX 관찰 결과(이 패턴을 vPDF에 그대로 반영):

1. 왼쪽 세로 **모드 레일**로 작업 모드를 전환합니다.
2. 모드마다 **상단 서브 툴바**가 바뀝니다(예: 주석 모드는 도구, 색, 크기).
3. 왼쪽 **썸네일 패널**과 가운데 **연속 스크롤 뷰어**를 사용합니다.
4. 페이지 구성 모드는 **카드 그리드**에서 드래그로 정렬하고 페이지별 회전·삭제·삽입 버튼을 제공합니다.
5. 도구는 **사이드 패널의 접이식 섹션**으로 노출합니다.

## 5. vPDF: 비슷한 프로그램 구현

브라우저에서 동작하는 PDF 도구입니다. 모든 처리는 로컬에서 하며 서버 업로드가 없습니다.

| 기술 | 역할 |
| --- | --- |
| Vite + TypeScript | 빌드, 프레임워크 없는 UI |
| pdf.js (`pdfjs-dist`) | 렌더링, 썸네일, 텍스트 추출/검색, 이미지 변환 |
| pdf-lib | 병합, 분할, 페이지 구성, 주석 적용, 워터마크, 페이지 번호, 메타데이터, 이미지 → PDF |
| Vitest / Playwright | 코어 단위 테스트 / 실제 UI E2E 테스트 |

### UPDF 기능 대비 구현 현황

| UPDF 기능 | vPDF | 구현 방식 / 한계 |
| --- | --- | --- |
| 읽기, 썸네일, 확대/축소, 페이지 이동 | 구현 | pdf.js 연속 스크롤 뷰어, 지연 렌더링(IntersectionObserver) |
| 텍스트 검색 | 구현 | 페이지별 텍스트 추출 후 검색, 결과 클릭 시 해당 페이지로 이동 |
| 형광펜 / 사각형 / 펜 / 텍스트 / 도장 / 흰색 지우개 / 이미지 | 구현 | SVG 오버레이에서 편집하고, 적용 시 PDF 콘텐츠에 굽기(flatten) |
| 메모(스티키 노트) | 구현 | 실제 PDF `/Text` 주석으로 저장해서 다른 뷰어에서도 보임 |
| 한글 텍스트/도장/워터마크 | 구현 | 표준 14폰트는 한글을 인코딩하지 못해서 캔버스로 PNG를 만들어 삽입 |
| 실행 취소 / 다시 실행 | 구현 | 문서 바이트와 대기 중 주석의 스냅샷 히스토리(최대 50단계) |
| 페이지 회전, 삭제, 빈 페이지 삽입, 드래그 정렬 | 구현 | `organize(plan)` 한 번에 적용 |
| 병합, 분할(N페이지), 범위 추출/삭제 | 구현 | pdf-lib `copyPages` |
| 워터마크, 페이지 번호 | 구현 | 페이지 번호는 회전되지 않은 페이지 좌표 기준 |
| PDF → PNG/JPG/TXT, 이미지 → PDF | 구현 | pdf.js 래스터화(2배), 텍스트 추출, pdf-lib 이미지 임베드(A4 맞춤) |
| 문서 속성(메타데이터), 최적화 | 구현 | 최적화는 객체 스트림으로 다시 저장(이미지 재압축은 하지 않음) |
| 한/영 UI | 구현 | 브라우저 언어로 자동 선택, 토글 가능 |
| 기존 텍스트 직접 편집 | 부분 구현 | 흰색 지우개와 텍스트로 대체(콘텐츠 스트림 편집은 하지 않음) |
| Office 변환, OCR, AI, 암호화, 가리기, 양식, 디지털 서명 | 미구현 | 레이아웃 분석/OCR 엔진/LLM/암호화 라이브러리가 필요해서 범위 밖. 확장 지점은 6장 참고 |

### 코드 구조

```text
src/core/pdf-ops.ts  순수 함수(바이트 입력 → 바이트 출력): merge, organize, splitEvery, extract/delete/rotate,
                     addWatermark, addPageNumbers, imagesToPdf, get/setMetadata, optimize, applyAnnotations
src/core/text.ts     텍스트 추출, 검색, TXT 내보내기(pdf.js 문서 인터페이스만 의존)
src/ui/*             i18n(한/영), DOM 유틸, 캔버스 래스터화(한글 텍스트 → PNG)
src/main.ts          앱 상태, 뷰어, 주석 오버레이, 페이지 구성 그리드, 도구 패널 연결
tests/unit           코어 로직 Vitest 테스트(pdf.js로 결과 PDF를 다시 읽어서 검증)
tests/e2e/smoke.mjs  Playwright로 실제 UI를 조작하고 저장한 PDF를 검증
```

핵심 설계 결정은 세 가지입니다.

- **문서는 불변 바이트**: 모든 작업은 `Uint8Array → Uint8Array` 함수이고, 결과로 뷰어를 다시 로드합니다. 그래서 실행 취소는 스냅샷 교체만으로 됩니다.
- **주석은 대기 후 일괄 적용**: 화면에서 자유롭게 추가하고 지울 수 있으며, 저장하거나 다른 작업을 할 때 자동으로 적용합니다.
- **좌표는 PDF 사용자 공간**에 저장합니다(`viewport.convertToPdfPoint`). 그래서 확대/축소와 무관하고 회전된 페이지에서도 정확합니다.

## 6. 향후 확장

1. **OCR**: tesseract.js로 페이지 이미지를 인식하고, 보이지 않는 텍스트 레이어를 추가합니다.
2. **AI 요약/번역/채팅**: `extractPageTexts` 결과를 LLM API로 보냅니다(키는 서버에서 관리).
3. **암호화/가리기**: qpdf(wasm)나 서버 측 처리가 필요합니다.
4. **실제 주석 객체**: 형광펜과 잉크도 `/Highlight`, `/Ink` 주석으로 저장해서 다시 편집할 수 있게 합니다.
5. **Office 변환**: 텍스트 블록 좌표를 이용해 DOCX를 생성합니다(레이아웃 분석 필요).
6. **데스크톱 앱**: Tauri나 Electron으로 감싸서 파일 시스템과 연동합니다.
